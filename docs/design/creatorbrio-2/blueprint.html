Part 4 · Delivery

Implementation blueprint

Three milestones, each shippable on its own, each leaving no dead link behind. Nothing here starts before the founder approves the direction and the decisions it depends on.

Gate

Milestone 2 starts only after founder approval of the visual direction and of decisions D1, D2, D3, D5, D6, D7, D10, D12, D13, D14 and D15. Each milestone begins with its own GitHub issue, validated with the repository's ticket validator, and ends with its own pull request.

Principles for the build

  • One engine. Every format is a carousel. No second project model, no second editor, no second export path.
  • Additive data. New fields are optional and have a meaning when absent; no stored record is rewritten; no route changes its response for existing callers.
  • No dead ends at any milestone. M2 links Projects, Templates and Brands to working pages built from today's components; M3 replaces them.
  • The design agent is not touched. Its system prompt is frozen and pinned by a test (docs/architecture/design-decisions.md). Format guidance travels as visible words in the person's own message.
  • The Video Studio is left as it is. 2.0 adds an entry page and aligns its top bar. The one change near its API is an additive status form of the session route (D15); the Production API, store and media registry are not touched.

Milestone 2 · App shell, Home and the creation flow

Outcome
Every format, the Video Studio and Settings are reachable from the first screen; a new person can start without a modal; primary actions pass AA; Home works on phones.
Scope
  • Design tokens: repoint globals.css as in the migration table, add brand, line-strong, status and studio tokens.
  • App shell on /, /projects, /templates, /brands, /studio and /settings: sidebar, icon rail, phone top bar, tab bar and More sheet, brand switcher.
  • Home: format cards, quick create, Continue creating, template strip, Studio panel, brand panel, Claude Code banner, first-run brand card (replacing the automatic BrandSetup modal), loading, empty and error states.
  • Creation flow replacing the create dialog: format, brand, size, description or template, optional name.
  • /projects and /templates as today's grids moved into the shell, with keyboard-reachable cards (A3); /brands as a list that opens today's brand editor.
  • /settings; the Video Studio entry content around today's StudioApp.
  • Copy fixes A10, A11, A17 and A20.
Reuses
Button, Badge, Input, Notice, ConfirmDialog (Radix Dialog), useBrandSelection, BrandSelector logic, BrandSetup (from Brands and the first-run card), CarouselCard and TemplateGallery (moved), StudioApp, PairingPanel, ProductionPicker, StudioApi, SlideRenderer for previews, src/lib/export-formats.ts for each format's export line.
New
AppShell, Sidebar, MobileTopBar, TabBar, MoreSheet, BrandSwitcher, FormatCard, CreateFlow, QuickCreate, RecentProjects, StudioHomePanel, BrandSummaryPanel, FirstRunBrandCard, SettingsPage, a Menu primitive (D12) and a Toast. A format registry in src/lib/formats.ts holding each format's name, default size, sizes, slide limit and default export. An optional initialDraft on ChatInput.
Data model
Optional format on Carousel in src/types/carousel.ts: "instagram-carousel" | "linkedin-document" | "reel-cover". Absent reads as "instagram-carousel". Set at creation; not in pickCarouselUpdate in this milestone. No stored record is rewritten.
API
  • POST /api/carousels accepts an optional format; an unknown value is refused with 400 and a reason. A Reel cover is created at 9:16 whatever size is sent.
  • GET /api/carousels?view=summary (with the existing optional brandId) returns per carousel: id, name, brandId, format, aspectRatio, slide count, the first slide's HTML, createdAt and updatedAt. No other slide HTML and no undo history. Without view, the response is unchanged.
  • GET /api/status, read-only: Claude Code available or not (reusing the /api/chat/check logic) and whether an image service is configured (imageGenerationConfigured(), which makes no network call). Whether it answers would need a new short loopback probe and is left out. No paths, URLs or secrets in the response. Behind the same loopback and origin rules as every route in src/proxy.ts.
  • The session status form (D15): GET /api/video/session with an explicit status parameter answers 200 with { paired: false } instead of 401, under the same cookie, header and origin rules. Without the parameter, the route answers exactly as today.
  • PUT /api/carousels/[id] refuses an aspectRatio other than 9:16 for a Reel cover, so the format's rule holds on the server, not only on screen. Carousels without a format are unaffected.
  • A project's name stays required by POST /api/carousels; the creation flow derives one from the description when the person leaves the field empty, as the prototype does.
  • The idea typed on Home reaches the editor through sessionStorage keyed by the new carousel's id, is cleared once read, and is never sent automatically.
Migration risks
  • The token repoint changes every screen, including the editor. Intended, but it needs a visual pass of every route at five widths.
  • tests/chat-notice-contrast.test.ts reads the real globals.css; it must stay green and is the model for a new app-wide contrast test.
  • /start recognises the app by its page title (tests/docs-consistency.test.ts); keep the title or update the pattern with it.
  • The selected-brand key framewoven:selected-brand must not be renamed, or every browser loses its choice.
  • Removing the automatic first-run modal must not remove a way to create the first brand.
  • /studio keeps its pairing and session behaviour exactly. Outside the Studio, the shell asks about pairing only through the D15 status form, so no page logs a 401.
  • The browser tests below use the built-app harness, which skips without a fresh production build, and CI today runs npm test before npm run build. Without the CI change listed under dependencies, those tests would pass by skipping.
Dependencies
Founder approval (see the gate). If D12 is approved, @radix-ui/react-dropdown-menu, from the same family as the dialog the app already uses. A CI change: build before the built-app browser tests run (or a job that runs them after npm run build), and make those tests fail rather than skip under CI, as tests/chat-notice-contrast.test.ts already does for its browser.
Acceptance criteria
  • Home shows Instagram Carousel, LinkedIn Document, Reel Cover and Video Studio, each saying what it exports.
  • Video Studio and Settings are reachable from every shell page, with the keyboard and on a phone.
  • Creating a Reel cover makes a 9:16 carousel with format: "reel-cover" and opens the editor with "A one-slide Reel cover." and the description in the composer, unsent.
  • Creating a LinkedIn document stores format: "linkedin-document"; existing carousels load and open unchanged.
  • The active brand is preselected in the creation flow; a new brand set up from the first-run card becomes active.
  • Every text and control pair passes AA, measured by a test against the real stylesheet.
  • No page in the shell scrolls sideways at 390 or 320 pixels.
  • GET /api/carousels without view returns exactly what it does today.
  • README, CLAUDE.md and the API list describe the new routes, parameters and screens.
Regression coverage
  • Unit: the format registry; format validation; the summary projection never includes undo history or slides after the first.
  • Route: POST /api/carousels with each format, with none and with an unknown one; a Reel cover refusing a size change; summary and full list shapes; /api/status response has no paths or URLs; the session status form answering 200 unpaired and paired, and the route without it unchanged.
  • Browser, on the built-app harness in tests/helpers/studio-app.ts (temporary data, no Claude CLI on its path), running in CI after the build: Home's four formats; Tab reaches a recent project and Enter opens it; create a Reel cover and land in the editor at 9:16 with the composer prefilled and no chat request made; Studio link present; no sideways scroll at 390 and 320.
  • Contrast: extend the chat-notice approach to buttons, links, inputs and banners.
  • Existing suites unchanged: carousel contract, brands, brand selection, export, Studio end to end.
Complexity
Large. Mostly new presentation code over existing data; the riskiest parts are the token repoint, keeping /studio's session behaviour exact, and the CI change.

Milestone 3 · Projects, Templates and Brands

Outcome
A library that stays fast and findable at hundreds of projects; templates that are safe to manage; brands edited on a page with a live preview.
Scope
  • Projects: search, This brand or All brands, format filters with counts, sort, grid and list, 24 at a time; a visible More menu on every card (A6) with Duplicate, Save as template and confirmed Delete; empty, no-match, loading and error states; Videos filter for paired browsers.
  • Lazy first-slide thumbnails: one sandboxed iframe per card on screen, nothing for cards off screen (D11).
  • Templates: format filter, confirmed delete (A7), error state and a message when Use template fails (A19).
  • Brands page and /brands/[id] editor with a sticky live preview; New brand.
Reuses
M2's shell, summary view, menu and toast; ConfirmDialog; /api/carousels/[id]/duplicate; POST /api/templates and /api/templates/[id]/use; ColorPicker, FontSelector, LogoUpload, StyleKeywordPicker, CarouselBrandBadge; SlideRenderer for thumbnails and the brand preview; StudioApi for the Videos filter.
New
ProjectsPage, ProjectCard, ProjectRow, ProjectFilters, LazySlideThumb, TemplatesPage, BrandsPage, BrandTile, BrandEditorPage, BrandPreview.
Data model
Optional format on Template, copied from the source carousel when a template is saved; absent reads as Instagram Carousel. A carousel made from a template takes the template's format. A Video Studio production already has a format field that is an object (width, height, frame rate); the combined Projects list keeps the two apart with a separate kind rather than reusing the name.
API
  • The summary view gains q, format, sort (edited or name), limit (at most 100) and an opaque cursor that encodes the active sort key and the id, with per-format counts. Invalid values are refused with 400.
  • GET /api/templates includes each template's format.
  • POST /api/templates/[id]/use accepts an optional body with a name; without one it names the carousel as today. createCarousel accepts the format it passes on.
Migration risks
  • The store is one JSON file, so every summary request reads it whole. Fine for hundreds and low thousands; an index is a separate decision if that changes.
  • Paging while projects are edited can skip or repeat a card; the cursor is stable for a single session's view and the page says when it refreshed.
  • Many iframes at once cost memory; the thumbnail must render only on screen and only the first slide.
  • BrandSetup's modal and the new page must not diverge; the page reuses its field components rather than copying them.
Dependencies
M2 merged. D8, D9 and D11 approved.
Acceptance criteria
  • With 300 synthetic projects, Projects shows the first 24 and their counts, and search narrows the list on the server.
  • Every card action is reachable by keyboard and touch; Delete asks first.
  • Deleting a template asks first; a failed load or Use template says so.
  • A brand is edited on its own page and the preview follows every change before saving.
  • No more iframes exist than cards on screen.
Regression coverage
Route tests for every summary parameter, its limits and its 400s; cursor paging over a fixture of 300 in both sorts; template format inheritance; Use template with and without a name; browser tests for search, filters, card menu, confirmed deletes and the brand editor; a check that off-screen cards mount no iframe.
Complexity
Medium to large. The library and paging are the bulk; Templates and Brands mostly recompose existing parts.

Milestone 4 · Editor integration

Outcome
The editor belongs to the new product: labelled, format-aware and usable on a phone, with its design engine unchanged.
Scope
  • Top bar: back to Projects, the existing inline rename, format and brand chips, a More menu (Duplicate, Save as template with a confirmation toast, closing #158, and Delete), and Export whose main action is the format's default.
  • Labelled tools: Size as a menu (a fixed label for a Reel cover), Caption (shows CaptionPanel), Safe zones, Full screen.
  • Phones: Preview and Chat tabs, closing #170.
  • Add a slide puts "Add a slide that" into the composer; a Reel cover has no add button.
  • The Studio already has a top bar with a back link; it is aligned with the app's new top bar and goes back to the Studio entry, with no change to the Studio's behaviour.
Reuses
ChatPanel, ChatInput, RunNotice, useGenerationStatus, InterruptedExportNotice, CarouselPreview, SlideRenderer, SlideFilmstrip, SafeZoneOverlay, FullscreenPreview, CaptionPanel, ExportButton, AspectRatioSelector's options, TopBar's rename.
New
EditorTopBar, EditorTools, EditorTabs, SizeMenu.
Data model
None, unless D4 makes the format changeable; then format joins pickCarouselUpdate.
API
None, unless D4: then PUT /api/carousels/[id] accepts format with the same validation as creation.
Migration risks
  • The chat run, its notices, Continue and accept, and Export's 409 rules are intricate; the editor's frame changes around them, not through them.
  • The default export depends on format and slide count. export-formats.ts offers the single PNG only for a one-slide carousel, so a Reel cover that ended up with more than one slide defaults to the ZIP.
  • Moving Delete into a menu changes muscle memory; the confirmation stays.
Dependencies
M2 merged; M3 is not required. D4 and D13 approved.
Acceptance criteria
  • Every editor control has a visible label or a tooltip and an accessible name.
  • Export's main action downloads PNG images for a carousel, a PDF for a document and one PNG for a one-slide cover.
  • Save as template confirms success or says why it failed.
  • At 390 pixels the canvas fills the width under a Preview and Chat switch.
  • Stop, interrupted, accept, Continue and the export refusal behave exactly as before.
Regression coverage
The existing export, export-readiness, chat-stream and generation suites unchanged and green; browser tests for the phone tabs, the format-aware export default, the Save as template toast and the size menu; a Studio end-to-end pass to prove the workspace frame changed nothing.
Complexity
Medium. Contained to one page, with careful work around the chat run.

Across milestones

  • Documentation in the same change: README's screens and capability table, CLAUDE.md's architecture and API list, and a new docs/architecture/app-shell.md for the shell, routes and format registry.
  • Security: new routes sit behind src/proxy.ts's loopback and origin rules; inputs are validated through src/lib/api-input.ts; /api/status returns no paths, URLs or secrets; slide previews keep sandbox="".
  • No paid runs in tests: browser tests use the built-app harness, which has no Claude CLI on its path.
  • Rollback: each milestone is one pull request. Reverting it leaves data readable, because every new field is optional and every old path still works.

Not in scope

  • Changes to the design agent's prompt, the Visual Director or the export renderer.
  • Any change to the Production API, its store or media registry.
  • Brand deletion, custom font uploads and style presets (#159).
  • Publishing, scheduling, analytics, accounts or a hosted version.
  • Dark mode for the light interface.
