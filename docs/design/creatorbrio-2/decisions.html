Part 5 · For the founder

Decisions

Fifteen choices that are yours to make. Each has a recommendation; approving the package with no notes accepts all fifteen. The milestone each one blocks is named, so a decision can wait until its milestone if you prefer.

Direction

D1Visual direction · blocks M2

Light first, warm neutrals, Geist, one accent, the work as the only bright colour. Alternatives: keep today's cool greys and only fix contrast; or a darker, studio-first look across the whole app.

Recommended: approve the warm, light direction. It suits a tool whose output is colourful and whose users judge colour; the Studio keeps the black stage behind its video preview.

D2The accent's two jobs · blocks M2

Keep #e94560 for identity, focus and indicators, and use #bf394f for buttons and text. Alternatives: #e94560 everywhere with dark text on buttons, which looks muddy; or one darker accent everywhere, which dulls the mark.

Recommended: the split. It is the only option that keeps the identity and passes AA.

Data and formats

D3How a project knows its format · blocks M2

Store an optional format on each carousel, absent meaning Instagram Carousel. The alternative is to infer it from size and slide count, but a one-slide 9:16 carousel and a Reel cover look the same, and a document and a carousel at 4:5 look the same.

Recommended: the optional stored field. It is additive, needs no migration, and says what the person meant.

D4Can a project's format change later? · blocks M4

The format only sets defaults (export, sizes, add-slide), so changing it is safe. Fixing it at creation, like the brand, is simpler to explain.

Recommended: fixed at creation in M2 and M3; allow "Change format" in M4's More menu only if people ask for it. Duplicate covers most needs.

D5How a Reel cover stays one slide · blocks M2

The design agent's system prompt is frozen and pinned by a test, so the format cannot be added there without reopening that decision. Options:

  1. Advisory, visible: the composer is prefilled with "A one-slide Reel cover." before the person's description, which they can read and edit; the editor offers no add-slide button.
  2. Binding in the plan: the Visual Director receives the format and its slide limit as a constraint and plans exactly one slide. Needs a Director change and tests.
  3. In the design agent's prompt: not recommended; it reopens a frozen, tested decision.
Recommended: option 1 in M2, verified with one approved live run before M2 ships; option 2 as a follow-up if covers come back with more than one slide.

Structure

D6First run · blocks M2

Replace the automatic five-step brand modal with an inline "Set up your brand" card on Home. Until it is done, the default brand is used. The alternative keeps today's modal, which can be closed but opens again on every visit until the brand has a name, and stops it reopening.

Recommended: the inline card. The first thing a person sees should be what CreatorBrio makes.

D7A Settings page · blocks M2

A real page for Claude Code status, the image service, Studio pairing, data location and privacy, at the foot of the sidebar. The alternative is no Settings and a status line in the sidebar.

Recommended: the page. Each of those questions has no home today, and the gear that says Settings already exists.

D8Templates as a destination · blocks M3

Templates in the main navigation, or a filter inside Projects.

Recommended: its own destination. Starting from something and finding something are different intents, and the template list stays short.

D9Videos inside Projects · blocks M3

Show Video Studio productions as a Videos filter in Projects, for browsers that are paired, or keep them only in the Studio.

Recommended: the filter, as a read-only list that opens the Studio. Every production is stored under the default brand today, so the list does not filter videos by brand, and says so. It needs D15.

D10Quick create does not send · blocks M2

"Start from an idea" creates the project and fills the composer, but does not start the design. The alternative sends at once.

Recommended: fill, do not send. A design is a paid run of a few minutes; the person should see and confirm what is sent.

Engineering

D11Project thumbnails · blocks M3

Lazy live previews (a sandboxed iframe of the first slide, only for cards on screen), or PNG thumbnails cached when a project is saved or exported.

Recommended: lazy live previews first; they are always current and need no storage. Add cached PNGs only if a measured library is slow.

D12A menu primitive · blocks M2

Add @radix-ui/react-dropdown-menu, from the same family as the Radix Dialog the app already uses, or hand-build menus.

Recommended: add the Radix menu. Keyboard, focus and screen-reader behaviour in menus is where hand-built UI fails, and the family is already trusted here.

D13The editor's address · blocks M2

Keep /carousel/[id] for every format, or move to /projects/[id] with a redirect.

Recommended: keep it. Bookmarks, tests and docs use it; the name in the address is not something people read.

D14Video Studio on phones · blocks M2

On a phone, the Studio offers pairing, the productions list and render status, and says the timeline needs a larger screen. The alternative is a phone timeline.

Recommended: list only on phones. A usable phone timeline is its own project.

D15Knowing whether a browser is paired · blocks M2

Home's Studio panel, Settings and the Videos filter need to know whether this browser is paired. Today the only way to ask is the Studio's session route, which answers 401 when it is not, so every unpaired visit to Home would log an error. Options: an additive status form of the session route that answers "not paired" with a 200; or never ask outside the Studio, and show a plain link there.

Recommended: the additive status form, with the same cookie, header and origin rules as the route today. It is the one change this proposal makes near the Studio's API, it adds no authority, and it also removes the 401 noise the Studio page logs before pairing (audit A16). The Production API, store and media registry stay untouched.

Risks and known limitations of this package

  • The editor in the prototype is representative. The chat, run notices, filmstrip editing and exports are the existing ones and are not redrawn; the capability matrix says where each lives.
  • The Studio was not audited live. The pairing script documents a non-interactive option that the repository's tests use, but this session's permission policy refused it, and that was respected. Studio findings come from source and the README's screenshot. A live pass against an isolated instance, run or approved by you, would close this gap.
  • No design run was started while auditing, so the timing claims are the README's ("a few minutes").
  • D5 is untested live. Whether the prefilled words reliably yield one slide needs one approved run before M2 ships.
  • Fonts load from Google in both the prototype and these pages; offline, they fall back to system fonts and look slightly different.
