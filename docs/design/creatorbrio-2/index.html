Founder review · issue #172

From a carousel dashboard to a creative studio

CreatorBrio already makes Instagram carousels, LinkedIn documents, Reel covers and Reels. Its first screen shows only carousels, and its Video Studio has no link at all. This proposal reorganises the product around what people make, keeps every capability it has, and is honest about what is early.

Your approval is the gate

Nothing here is implemented, and no application code was changed. Milestone 2 starts only after you approve the visual direction and the decisions it depends on. The pull request carrying this package stays a draft and is not merged without that approval.

The proposal in brief

  1. A studio, not a dashboard. A persistent sidebar with Home, Projects, Templates, Brands and Video Studio, Settings at its foot, and the active brand at the top. Phones get a five-tab bar.
  2. Start from what you are making. Home asks "What would you like to create?" and offers Instagram Carousel, LinkedIn Document, Reel Cover and Video Studio, each saying what it exports. All three slide formats run on today's carousel engine and editor.
  3. Formats with sensible defaults. A Reel cover is one 9:16 slide exported as one PNG; a LinkedIn document is portrait and exports a searchable PDF. The format is one optional field on a carousel; existing projects open unchanged.
  4. A library that scales. Projects searches, filters by format and brand, sorts and pages, with real first-slide previews and actions people can reach without a mouse.
  5. An honest Video Studio. Linked from everywhere, tagged Early, with a plain list of what works today and what is not built.
  6. A warm, accessible look. Warm neutrals, Geist and the existing coral kept as the identity colour, with a deeper shade for buttons and text so every pair passes WCAG AA.

Process and checks

  • Issue #172, validated with the repository's ticket validator; work on branch docs/172-creatorbrio-2-product-experience in its own worktree; a draft pull request.
  • Isolation. The current app was audited from a separate instance with its own port and data folder. The founder's checkout, data and app were not touched.
  • Changes are confined to this folder. No application code, API, data format or workflow changed.
  • Checks. Every page and prototype screen at 1440, 1280, 768, 390 and 320 pixels with no sideways scrolling; keyboard paths; contrast measured; the repository's typecheck, lint, tests and build pass with the package in place.
