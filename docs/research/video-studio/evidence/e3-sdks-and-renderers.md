# 03 — Embeddable editing SDKs, timeline UI components, rendering frameworks

Research date: 2026-11-03. Method: blobless clones (history/metadata) in `<local clone>/<owner>_<repo>`, shallow `--depth 1` clones (source reading) in `<local clone>/<owner>_<repo>`, npm tarballs (read-only, never installed or executed) in a local npm tarball folder. Nothing was run, built or installed. "90d" = commits since 2026-08-05 on the default branch. Items I could not verify are marked **[unverified]**. `www.remotion.pro` was not reachable from this sandbox (DNS blocked), so the Remotion Store license texts for Editor Starter / Timeline could not be read.

CreatorBrio context that drives the evaluation: Next.js 16 / React 19 / Tailwind v4 app; slides are body HTML wrapped by `wrapSlideHtml()`, previewed in `sandbox=""` iframes and exported by Puppeteer screenshots (`puppeteer ^24.40` in `package.json`). The repo is public and MIT-licensed; users run it locally. So: (a) license terms bind every end user who runs CreatorBrio, not only the maintainers; (b) preview==export is already "same HTML, Chromium screenshot"; (c) `sandbox=""` (no JS) is a current invariant that any time-based motion system must either respect (CSS-only animation seeked from outside) or deliberately relax.

## 1. Remotion (remotion-dev/remotion)

- **Classification:** complete framework (React composition model + Player preview + server renderer + client renderer + many add-ons). Not a ready-made editor; editor/timeline UIs are separate paid products.
- **HEAD:** `cd1bb77f35b839a6fdcd64765725749409c3f4e5` (2026-11-03). **90d commits:** 5,529. **Latest tag:** `v4.0.540` (2026-11-02); releases roughly weekly (v4.0.538 2026-10-22, v4.0.539 2026-10-26). Extremely active.
- **License (read `LICENSE.md` + docs `terms.mdx`, `license/faq.mdx` in repo):** *source-available, not OSI open source* — docs say so explicitly ([faq.mdx L326](https://github.com/remotion-dev/remotion/blob/cd1bb77f35b839a6fdcd64765725749409c3f4e5/packages/docs/docs/license/faq.mdx#L326)).
  - Free License eligibility: individuals; for-profit orgs **up to 3 employees**; non-profits; evaluation ([LICENSE.md L16-L33](https://github.com/remotion-dev/remotion/blob/cd1bb77f35b839a6fdcd64765725749409c3f4e5/LICENSE.md#L16-L33)). Headcount = all personnel incl. contractors; collaborating parties' headcount aggregates ([terms.mdx L276-L284](https://github.com/remotion-dev/remotion/blob/cd1bb77f35b839a6fdcd64765725749409c3f4e5/packages/docs/docs/terms.mdx#L276-L284)).
  - Modification: allowed "to their own liking, for the purpose of fulfilling their custom use case or to contribute back". **Disallowed:** copying/modifying Remotion "for the purpose of selling, renting, licensing, relicensing, or sublicensing your own derivative of Remotion". No general redistribution grant for modified Remotion source.
  - Company License (4+ headcount): "Remotion for Creators" $25/seat/month, or "Remotion for Automators" $0.01/render, min $100/month. **Automation is defined as owning code that calls `renderMedia()`, `renderMediaOnWeb()`, CLI render, … or `<Player>`**; "organizations building video editors, prompt-to-video tools … or using the Remotion Player will fall under Remotion for Automators" ([faq.mdx L106-L129](https://github.com/remotion-dev/remotion/blob/cd1bb77f35b839a6fdcd64765725749409c3f4e5/packages/docs/docs/license/faq.mdx#L106-L129)).

  - Distributed native apps need an abstraction layer between end user and Remotion code; Company-License holders must keep the license for one year after the last release ([terms.mdx L343-L349](https://github.com/remotion-dev/remotion/blob/cd1bb77f35b839a6fdcd64765725749409c3f4e5/packages/docs/docs/terms.mdx#L343-L349)). An end user who can view/modify Remotion code is themselves a Remotion User and needs their own Company License if ≥4 headcount ([terms.mdx L351-L353](https://github.com/remotion-dev/remotion/blob/cd1bb77f35b839a6fdcd64765725749409c3f4e5/packages/docs/docs/terms.mdx#L351-L353)); exported Remotion projects must carry attribution + license link ([L355-L359](https://github.com/remotion-dev/remotion/blob/cd1bb77f35b839a6fdcd64765725749409c3f4e5/packages/docs/docs/terms.mdx#L355-L359)).
  - **Remotion 5.0** (announced, PR #3750): contractors count toward team size; company license bound to new T&Cs; telemetry (license key) mandatory for Automators. Client-side rendering (`@remotion/web-renderer`) **always** sends a telemetry event per render, even without a license key, and it cannot be disabled (`telemetry.mdx`).
  - **Per-package licenses differ** (from each `package.json` at HEAD): `remotion`, `@remotion/player`, `@remotion/renderer`, `@remotion/web-renderer`, `@remotion/google-fonts`, `@remotion/install-whisper-cpp` → "SEE LICENSE IN LICENSE.md" (Remotion License); `@remotion/media-parser`, `@remotion/webcodecs`, `@remotion/sdk` → Remotion License; **MIT:** `@remotion/captions` (zero deps), `@remotion/video-matting` (deps only `mediabunny`, `onnxruntime-node`, peer `@huggingface/transformers`), `@remotion/sfx`, `@remotion/timeline-utils` (but depends on `remotion`), `@remotion/layout-utils`, `@remotion/openai-whisper`, `@remotion/elevenlabs`, `@remotion/licensing`, `@remotion/studio`; `"UNLICENSED"` in package.json for `@remotion/transitions`, `@remotion/effects`, `@remotion/whisper-web` (no package-level LICENSE file; root Remotion License presumably applies **[unverified]**).
  - **Implication for CreatorBrio (needs legal review, not legal advice):** CreatorBrio is MIT and self-hosted by each user. Bundling Remotion makes every user a Remotion User: solo creators and ≤3-person companies are free; an agency/brand team of 4+ using CreatorBrio's Video Studio would need a Company License, very likely the Automators plan since the app embeds `<Player>` and calls render APIs. The agent writing Remotion code that the user can see/edit triggers the end-user code-access clause. This is a material, non-technical constraint on making Remotion a *mandatory* dependency of an MIT project.
- **Paid add-ons:** Editor Starter **$600 one-time** (free with Enterprise), private GitHub repo, React 19 + Tailwind v4 + TS, React Router 7 template with copy-paste Next.js endpoints; *not included*: keyframes, transitions, project management, multiple frame rates (fixed 30 fps), arbitrary fonts, light mode; captioning uses the OpenAI Whisper API (paid, 25 MB cap); default render path is Remotion Lambda (AWS), client-side WebCodecs render is a flag (`ENABLE_CLIENT_SIDE_RENDERING`). Features: multitrack timeline, drag/multi-select/marquee, trim handles, split, rolling edits, snapping, waveform, filmstrip, volume line, fades, undo/redo, inspector (docs `editor-starter/*.mdx`). `<Timeline>` component is also paid (price not in repo docs; refundable on Editor Starter upgrade). Both governed by Remotion License **plus** their own store license **[store license text unverified — remotion.pro unreachable]**; a private paid repo cannot reasonably be vendored into a public MIT repo.
- **Rendering pipeline (verified in source):**
  - Preview: `@remotion/player` renders the same React tree in the page DOM, driven by `useCurrentFrame()`.
  - Server/local export: `@remotion/renderer` launches Chrome Headless Shell (downloads `mac-arm64` build on Apple Silicon — [BrowserFetcher.ts L60](https://github.com/remotion-dev/remotion/blob/cd1bb77f35b839a6fdcd64765725749409c3f4e5/packages/renderer/src/browser/BrowserFetcher.ts#L60)), seeks each frame via `window.remotion_setFrame` and waits for all `delayRender()` handles ([seek-to-frame.ts L180-L213](https://github.com/remotion-dev/remotion/blob/cd1bb77f35b839a6fdcd64765725749409c3f4e5/packages/renderer/src/seek-to-frame.ts#L180-L213)), then grabs pixels with CDP `Page.captureScreenshot` ([screenshot-task.ts L72](https://github.com/remotion-dev/remotion/blob/cd1bb77f35b839a6fdcd64765725749409c3f4e5/packages/renderer/src/screenshot-task.ts#L72)); FFmpeg stitches; a Rust compositor (`packages/compositor-darwin-arm64` exists) extracts exact video frames for `<OffthreadVideo>`. Parallel tabs (concurrency) scale with cores — a 128 GB M-series Mac is a good fit.
  - Client export: `@remotion/web-renderer` (stable since v4.0.491) **does not screenshot**; it re-implements layout/painting onto canvas from `getBoundingClientRect()` + computed styles and encodes via Mediabunny/WebCodecs. Documented gaps: no `z-index` (DOM order only), no `backdrop-filter`, `background-blend-mode`, `perspective`, inset/spread shadows, `writing-mode`, non-gradient background images; filters unsupported in Safari; single-threaded ([limitations.mdx L161-L180](https://github.com/remotion-dev/remotion/blob/cd1bb77f35b839a6fdcd64765725749409c3f4e5/packages/docs/docs/client-side-rendering/limitations.mdx#L161-L180)). Optional "HTML-in-canvas" mode (`drawElementImage`) needs a Chrome flag and falls back silently. ⇒ **preview==export is reliable only on the SSR (screenshot) path**, not the client renderer, for arbitrary CSS.
- **Other components asked about:**
  - `@remotion/media-parser`: docs banner "We are phasing out Media Parser and are moving to Mediabunny" — don't adopt.
  - `@remotion/captions`: MIT, zero deps; `Caption` type, SRT/VTT parse/serialize, TikTok-style page grouping — safe to use standalone.
  - `@remotion/install-whisper-cpp`: Remotion License; installs whisper.cpp (docs example pins 1.5.5) + models, local transcription with token timestamps. Thin helper; the underlying whisper.cpp is MIT and can be driven directly.
  - `@remotion/video-matting` (new, first commit 2026-09-07, v4.0.523+): MIT; WebGPU matting in browser or Node with models `modnet` (person, Xenova/modnet, ~26 MB) and `ben2-base` (general, onnx-community/BEN2-ONNX, ~219 MB, needs shader-f16) ([models.ts](https://github.com/remotion-dev/remotion/blob/cd1bb77f35b839a6fdcd64765725749409c3f4e5/packages/video-matting/src/models.ts)); outputs opaque base + transparent VP9-alpha foreground — exactly the primitive for **text-behind-subject**. Models mirrored on `remotion.media`; model licenses separate **[unverified]**.
  - Agent skills: `packages/skills/skills/*` (remotion-best-practices, -captions, -create, -render, -license, …) installed via `npx skills add remotion-dev/skills`; `packages/claude-code-plugin` (package.json license "Remotion License", private). Docs page `export-opentimeline.mdx` is itself an agent skill that converts a composition to OTIO with pre-rendered fallbacks — Remotion states deterministic OTIO export is impossible because compositions are code.
  - `@remotion/sdk` (Remotion License): "in development", waitlist, API "subject to heavy changes" — in-browser compiler for React-code motion graphics; not usable yet.
  - Next.js: `@remotion/renderer` in Next is "not officially supported" when self-hosting; needs `serverExternalPackages: ['@remotion/renderer']`, and `@remotion/bundler` (Webpack) cannot run inside an API route — bundle out-of-band (`miscellaneous/nextjs.mdx`). Player embeds normally.
- **Feature matrix:** multitrack (via your own `<Sequence>` layout) ✔; clip trim (`trimBefore/trimAfter`) ✔; keyframes via `interpolate()`/`spring()` in code (no keyframe UI) ✔; transitions `@remotion/transitions` ✔; audio tracks/volume curves ✔ (mixing done in FFmpeg); canvas/Three/Skia/Lottie ✔; captions ✔; undo/redo ✘ (app concern); structured JSON project ✘ (compositions are code; you define props JSON + zod schemas); programmatic API ✔✔; preview-to-export same code path ✔ (same React components; Chromium screenshot). Extensibility excellent.
- **Apple Silicon:** native darwin-arm64 compositor + mac-arm64 headless shell; VideoToolbox hardware encoding available via `hardwareAcceleration` in renderMedia **[unverified for this version]**.

## 2. HyperFrames (heygen-com/hyperframes) — discovered alternative, directly relevant

- **Classification:** complete framework (HTML composition contract + player web component + Puppeteer/FFmpeg producer + headless SDK + studio). Probably covered in depth by another slice; summarized here because it is the strongest *HTML-native* renderer.
- **HEAD:** `a5a61213320c523875633a94ef96097456269136` (2026-11-03). **90d commits:** 2,989. **Tags:** v0.9.9 / v0.9.8 (both 2026-11-03). Pre-1.0, extremely fast-moving (API churn risk).
- **License:** root `LICENSE` Apache-2.0; most `packages/*/package.json` have no `license` field (only `@hyperframes/cli` declares Apache-2.0) — root license presumably applies **[confirm per package on npm]**. Some skills (`/reverse-any-video`, `/style-sampling`) are "HyperFrames Pro". CLI/studio has telemetry with opt-out (`studioRenderTelemetry.ts`, `telemetryIdentity` tests) **[default state unverified]**.
- **Pipeline:** compositions are HTML with `data-start`/`data-duration` clips and paused GSAP timelines registered on `window.__timelines` (docs `concepts/compositions.mdx`); the engine seeks and captures with Puppeteer + FFmpeg. Deterministic Chrome **BeginFrame capture is used only on Linux with headless-shell; macOS falls back to screenshot mode** ([browserManager.ts L872-L878](https://github.com/heygen-com/hyperframes/blob/a5a61213320c523875633a94ef96097456269136/packages/engine/src/services/browserManager.ts#L872-L878)); code contains darwin/arm64-specific memory and failure handling (e.g. CSS-3D + audio navigation timeouts on macOS arm64, `pageNavigationTimeoutErrorHint.ts`). `@hyperframes/sdk` = headless, framework-neutral HTML composition editing (open → query → edit by `data-hf-id` → serialize). `@hyperframes/player` = embeddable web component. Requires Node 22+, FFmpeg.
- **Fit:** closest to CreatorBrio's existing "agent writes HTML, Chromium screenshots it" model; but compositions need **script execution** (GSAP), which conflicts with `sandbox=""` previews.

## Answers to the specific questions

### Ready-made timeline component vs. extracting one from a full application?

**Use a small, permissively licensed UI-only component (or write the timeline yourself) on top of a CreatorBrio-owned JSON schema; do not extract from a full application.** Reasons from the code read:

1. **Coupling.** Every full-app timeline inspected is welded to its own store and playback engine: Clipkit's `CanvasTimeline.tsx` (1,980 lines) reads `@clipkit/editor-core`'s Zustand store and the BSL runtime; Twick's `timeline-view.tsx` is bound to `@twick/timeline`'s `TimelineEditor` and live player; OpenVideo's timeline is a closed fabric.js package; Ektie's model hard-codes a `video-0` "spine" and product-specific track types. Extraction means re-plumbing state, selection, undo, snapping and playback sync anyway — most of the work of writing one.
2. **License contamination.** The full apps carry the restrictive terms (Twick SUL, OpenVideo/Remotion two-tier licenses, Remotion Store licenses, AGPL Ektie, BSL Clipkit runtime). Only Apache/MIT pieces (Clipkit editor code, Ektie's frozen `1f44b94` snapshot, xzdarcy) can be legally lifted into an MIT repo.
3. **The hard part is not the widget.** A short-form reel timeline needs source in/out offsets, linked audio, waveform/filmstrip lanes (Mediabunny), caption/word lanes driven by transcript edits, and keyframe lanes. No ready-made component provides these; they must match CreatorBrio's own schema, which the agent (Claude CLI via curl) also edits. Owning the schema (+ undo as a reducer over it, as Ektie and Remotion Editor Starter do) is what matters.

Practical path: depend on (or vendor) **`@xzdarcy/react-timeline-editor` (MIT, ~3.2k LOC, React 19 compatible)** for drag/resize/snap/zoom/virtualization, render custom action content (filmstrip, waveform, caption words), and keep all editing semantics in CreatorBrio's own reducer. Study Clipkit's Apache-2.0 `CanvasTimeline`/`MixerRail`/`InterpolationPanel` and Remotion's free "Build a timeline" guide for patterns. If xzdarcy's DOM approach hits performance limits with many caption words, a custom canvas timeline (~2–4k LOC) is the fallback.

### Which timeline UI is best to embed into CreatorBrio's Next.js app?

1. **xzdarcy/react-timeline-editor** — only mature, MIT, UI-only option; low maintenance cadence (1.0 in Jan 2026) but small enough to fork.
2. Clipkit editor (Apache-2.0) — most feature-complete open timeline UI (keyframes, mixer), but depends on the BSL runtime, single maintainer, 4 months old; use as reference/extraction source, not as a dependency.
3. Remotion Timeline / Editor Starter — technically strongest integrated option with Remotion Player, but paid, private-repo code under Remotion License + store license; cannot ship in a public MIT repo **[store terms unverified]**.
Avoid: Twick (SUL, dormant since May 2026), OpenVideo/designcombo (closed engine, conflicting licenses), Ektie (AGPL; Apache snapshot is frozen and product-specific).

### Which renderer gives the most reliable preview==export for HTML/CSS/React motion graphics over video?

**Headless-Chromium, frame-seeked screenshot rendering of the very same document that the preview shows.** Only two inspected systems do this for real HTML/CSS: **Remotion SSR** (`@remotion/renderer`: seek → wait for `delayRender` → `Page.captureScreenshot` → FFmpeg, exact video frames via `<OffthreadVideo>` + Rust compositor) and **HyperFrames** (Puppeteer + FFmpeg, GSAP timelines seeked; BeginFrame on Linux, screenshot mode on macOS). Canvas engines (Twick, Revideo, Motion Canvas, Clipkit, OpenVideo, Diffusion Studio, etro) are internally consistent but are not HTML/CSS, so CreatorBrio's HTML brand templates and the agent's HTML skill would not carry over. Client-side WebCodecs renderers that re-paint DOM onto canvas (Remotion web-renderer) are explicitly *not* faithful to arbitrary CSS (no z-index, backdrop-filter, perspective…).

- **Technically most mature:** Remotion (years of hardening, frame-accurate video, arm64-native, huge add-on ecosystem incl. MIT `@remotion/captions` and `@remotion/video-matting`). **Blocker:** source-available license that binds every CreatorBrio user (free only for individuals / ≤3-person orgs / non-profits; Player use counts as "Automators" for companies; end-user code access clause; telemetry in web rendering). It must not be a *mandatory* dependency of an MIT project without an explicit maintainer/legal decision; at most an optional, user-installed backend.
- **Best license/stack fit:** an HTML-native seek-and-screenshot pipeline — either adopt HyperFrames (Apache-2.0; very active but pre-1.0 and requires script-driven GSAP timelines) or extend CreatorBrio's existing Puppeteer + `wrapSlideHtml()` contract with a time parameter (seek CSS/Web Animations via `document.getAnimations()` currentTime from the outside so slide documents can stay script-free), render motion-graphics layers as frame sequences or transparent ProRes 4444, and composite over source video with FFmpeg (VideoToolbox encode on Apple Silicon). This preserves the current "same HTML, Chromium screenshot" guarantee that the carousel export already relies on. [The in-house approach is a design proposal, not something verified in code.]

### Reusable building blocks regardless of renderer choice (permissive)
- **Mediabunny** (MPL-2.0, very active) — media probing, thumbnails, waveforms, WebCodecs I/O.
- **`@remotion/captions`** (MIT, zero deps) — caption types + SRT/VTT; **`@remotion/video-matting`** (MIT, no `remotion` dependency) — local WebGPU matting for text-behind-subject (model licenses to verify).
- **whisper.cpp** directly (MIT) rather than `@remotion/install-whisper-cpp` (Remotion License); or Transformers.js Whisper as in Clipkit's Apache `speech-to-text`.
- **OTIO JSON** as an export target (write the small subset directly; `otio.js` is a one-release community package).
